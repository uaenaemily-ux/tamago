## 第 0 步：规划与文档（2026-10-11）
- **问题**：PRD 文件名异常，显示为 `~:Projects:tamago:docs:PRD.md`
- **原因**：保存时把完整路径当成了文件名（macOS 中路径里的 `/` 会显示为 `:`）
- **解决**：重命名为 `docs/PRD.md`

## 第 1 步：页面骨架 + 字体（2026-10-11）
- **字体选择**：正文用系统自带的苹方（非苹果设备依次退回微软雅黑、思源黑体/Noto Sans CJK、文泉驿）；标题、数字、按钮用「秋叶圆体 16」截取后的 Tamago Title
  - 原因：对比站酷快乐体、M PLUS Rounded 1c、系统字体后，由用户选定（选择秋叶圆体的具体理由待补充）；正文用系统字体，不用下载、显示最稳定
- **问题**：秋叶圆体完整字体 3.3 MB，网页加载太慢
  - **原因**：中文字体包含上万个字
  - **解决**：用 `tools/subset-font.py` 只截取网页文案里用到的字，输出 `fonts/tamago-title.woff2`，约 10 KB
- **问题**：字体能不能用在网页上
  - **原因**：fonts/ 里没有授权文件，需要到原作者仓库核实
  - **解决**：字体使用 SIL OFL 1.1，可以免费用于网页；作者在 README 声明保留名称「秋叶圆体 16」「QiuYeYuanTi 16」，截取属于修改，所以截取版改名为 "Tamago Title"，保留原版权信息，并附上 `fonts/OFL.txt`
- **问题**：用户输入的名字（比如中文朋友名）不在截取范围里
  - **原因**：截取只包含代码里写死的文案
  - **解决**：这些字会自动用正文字体（苹方）显示，暂时接受；如果效果不好，以后再考虑加入常用 3500 字
- **问题**：点阵字体在某些字号下会发糊
  - **原因**：秋叶圆体是 16px 点阵字体
  - **解决**：标题字号只用 16 的倍数（16 / 32 / 48px），并禁止浏览器自动加粗（font-synthesis: none）

## 第 1 步补充：美术风格（2026-10-11）
- **风格决定**：甜美梦幻为主，保留天使元素；背景用粉白斜格纹；卡片用白底 + 粉色虚线边框；装饰同时使用手绘线条和像素小图标
  - 原因：用户查看 design-refs/ 参考图的风格总结后选定；斜格纹参考 design-refs/background.png
- **问题**：参考图里有原作角色、经典蛋纹样和现成角色（如三丽鸥），不能直接使用
  - **原因**：版权和 PRD 的原创性要求
  - **解决**：所有装饰都重新原创绘制（手绘闪光、天使翅膀、像素爱心 / 星星 / 翅膀 / 导航图标）；design-refs/ 已加入 .gitignore，不提交
- **问题**：主按钮"粉底白字"对比度只有 1.9，手机上看不清；灰色说明文字对比度只有 4.25
  - **原因**：浅粉背景上的白字太淡；灰色不够深
  - **解决**：主按钮改为粉底深色字（6.3）；说明文字加深到 #7A6470（5.4）；小字号强调色新增 --color-pink-700（4.85）
- **问题**：第一版格纹是横竖方格，和想要的效果不一样
  - **原因**：一开始没有指定格纹方向
  - **解决**：改为两组 45° 斜条交叉的菱形格纹，颜色调到很淡
- **备注**：iPhone 的 Safari 不支持 background-attachment: fixed，格纹会跟着页面一起滚，不影响使用

## 第 2 步：数据层（2026-10-11）
- **结果**：tests/ 测试页 29 项全部通过
- **问题**：jsDelivr 上 idb-keyval 的授权文件下载失败（404）
  - **原因**：这个包的授权文件名是英式拼写 `LICENCE`，不是 `LICENSE`
  - **解决**：按正确的文件名下载，保存为 `js/vendor/idb-keyval.LICENSE`
- **问题**：加入数据层后，截取的标题字体从 10.8 KB 涨到 25 KB
  - **原因**：截取脚本把代码注释里的中文也算进去了
  - **解决**：JS 文件只收集字符串里的文字，HTML 跳过注释，字体降到 14.5 KB
- **问题**：用局域网地址（http）在手机上测试时，持久存储显示 unsupported
  - **原因**：浏览器只在 https 或 localhost 下提供持久存储
  - **解决**：属于正常现象，GitHub Pages 是 https，部署后可以正常申请；生成 id 也改用 crypto.getRandomValues，在 http 下同样能用

## 第 3 步：添加 / 编辑朋友 + 目录页（2026-10-11）
- **结果**：电脑和手机测试通过；原创守护蛋、目录分区和分页、登记 / 编辑弹窗、删除二次确认都正常
- **问题**：`el()` 用 `style: { "--swatch": color }` 设置 CSS 变量时没有效果
  - **原因**：`Object.assign(node.style, …)` 不能设置 CSS 变量，必须用 `style.setProperty("--xxx", …)`
  - **解决**：`el()` 遇到 `--` 开头的属性改用 setProperty
- **问题**：手机上选蛋颜色的小圆圈全是白色，电脑上正常
  - **原因**：手机 Safari 缓存了修复前的旧 dom.js，`python3 -m http.server` 没有禁止缓存
  - **解决**：圆圈改为直接设置 backgroundColor，不依赖 CSS 变量；新增 `tools/serve.py`（Cache-Control: no-store）作为本地预览服务器；手机上清除一次该网站数据后恢复正常
- **问题**：没有 Node，无法在命令行检查 JS 语法
  - **原因**：电脑上没装 Node
  - **解决**：用 macOS 自带的 JavaScriptCore（`osascript -l JavaScript`）检查语法

## 第 4 步：详情页基础信息 + 标签（2026-10-11）
- **结果**：电脑和手机测试通过；年龄、星座、倒计时显示正确，标签可在详情页直接增删并保存
- **问题**：登记弹窗和详情页都需要标签输入，重复写两份代码容易不一致
  - **原因**：第 3 步时标签逻辑直接写在登记弹窗里
  - **解决**：抽成共用组件 `js/ui/tag-editor.js`，两处共用；保存失败时标签自动恢复原样并提示
- **问题**：在详情页改了标签后点"编辑"，弹窗可能拿到旧数据，保存时把新标签覆盖掉
  - **原因**：按钮点击时用的是页面渲染时的旧 person 对象
  - **解决**：点"编辑""删除"时都用 getPerson() 重新读取最新数据

## 第 5 步：礼物墙 + 添加礼物弹窗（2026-10-11）
- **结果**：电脑和手机测试通过；tests/ 33 项全部通过；照片可从相册选或拍照，压缩后方向正确
- **问题**：照片会占用浏览器的本地存储空间
  - **原因**：照片原图通常有几 MB
  - **解决**：在手机上用 canvas 压缩到最长边 800px、JPEG 质量 0.7（约 50–100 KB）；点"保存"后才写入，礼物保存失败时自动删掉刚存的照片；换照片或删除礼物时同时删除旧照片
- **问题**：导入的备份文件里的"照片"可能不是真正的图片
  - **原因**：备份文件来自外部，不可信
  - **解决**：显示照片前检查必须是 `data:image/...;base64,` 开头（isPhotoDataUrl），否则不显示
- **问题**：同一类礼物写法不统一（如"项链"和"饰品"）会影响以后 AI 判断同品类
  - **原因**：品类是自由输入
  - **解决**：品类和场合加输入建议（用过的排前面 + 预设词），引导用词统一

## 第 6 步：首页生日倒计时（2026-10-11）
- **结果**：大蛋区、小蛋横排、空状态、"下一个生日"提示完成；tests/ 41 项
- **改动：大蛋区从"最近那一天"改为"3 天内（含当天）"**
  - **问题**：一个朋友今天过生日、另一个 3 天后过生日时，大蛋区只显示今天的人，3 天后的人被挪到"30 天内还有"的小蛋里，很容易被忽略
  - **原因**：第一版大蛋区只放"最近那一天"过生日的人
  - **解决**：3 天内（含当天）过生日的人都放进大蛋区，按日期从近到远排序，多人时左右滑动、小圆点显示总数，每颗大蛋上方显示"Today!"或"In X Days"；"30 天内还有"只显示 3 天以外的人。"3 天"写成 `js/pages/home.js` 里的 `HERO_DAYS` 变量，方便以后调整
  - **补充**：3 天内没人过生日时，大蛋区放最近那一天的人（避免首页空着），小蛋区不重复显示 TA
- **改动：更新 logo**
  - **问题**：用户提供的 logo 原图是白底 PNG（1942×809，约 1.1 MB），直接用会在格纹背景上露出白框，而且太大
  - **原因**：原图没有透明背景；像素块大小不均匀（约 14–15px），无法精确转成像素 SVG
  - **解决**：按"离白色多远"计算透明度，颜色统一为 logo 粉（#DF7290），裁掉空白、缩到 640px 宽，再转成 32 色调色板 PNG，最终 `assets/logo.png` 约 11 KB；手机端显示在首页顶部，电脑端显示在侧边栏
- **问题**：手机上首页大蛋周围出现一圈淡淡的方形边框
  - **原因**：大蛋的粉色光晕用了 `filter: drop-shadow`，iPhone Safari 会把 SVG 的滤镜效果裁在它的方形范围内
  - **解决**：去掉滤镜，改为在蛋后面垫一层圆形的 radial-gradient 光晕（`.hero-egg::before`）

## 第 7 步：欢迎页 + 示例数据（2026-10-11）
- **示例数据标记**：人和礼物新增可选字段 `sample: true`，用于以后一键清除；没有该字段即真实数据，旧数据和旧备份不受影响，所以版本号保持 1、不需要迁移
- **问题**：已经登记过朋友的用户，欢迎页上线后会被当成"第一次打开"
  - **原因**：旧数据里 settings.onboarded 都是 false
  - **解决**：启动时如果已经有人，直接标记为看过欢迎页
- **问题**：欢迎页的蛋是粉色，但这时用户还没录入任何信息
  - **原因**：直接用了默认粉色
  - **解决**：改为白色"空白蛋"（egg-blank），描边、花边、圆点、高光、闪光换成淡粉，避免白上加白看不见
- **问题**：手绘天使翅膀在电脑上线条生硬，中间有一条颜色不同的粉线；在手机上发糊
  - **原因**：用了 feTurbulence + feDisplacementMap 的"抖动"滤镜，浏览器会先按低分辨率画好再放大，所以在高清屏上发糊；中间的粉线是单独用另一种颜色画的
  - **解决**：重画翅膀，不用滤镜、单一描边色。第一版平滑线条版用户仍不满意，按用户给的参考图改成圆胖卡通风（粗圆描边、3 片鼓起的羽毛、羽毛交界处的短线、根部小卷），路径为原创；每版都用 macOS 的 qlmanage 渲染预览确认
  - **最终**：用户改主意，换成柔和像素风天使翅膀（参考用户给的图的画风，像素图原创）：白色羽毛、淡粉紫边缘、无深色描边、上下两层羽毛、根部螺旋、周围小闪光。先用椭圆拼形状生成字符画草稿，再手工修整，加进 tools/pixel-icons.py 生成 `pixel-angel-wing.svg`；旧的 hand-wing.svg 删除。显示尺寸用整数倍（窄屏 2 倍、≥380px 3 倍），避免 320px 小屏出现横向滚动
- **AI 生成的翅膀图整理**（assets/wings-raw.png → assets/wings.png）
  - **问题**：背景看起来透明，但其实不干净：约 50 万个半透明像素（包括肉眼几乎看不见的灰色雾状残留和白边），翅膀主体本身也只有 98–99% 不透明，完全不透明的像素只有 2044 个；另外有几团灰色污渍；"像素块"大小不一（约 12–13px），不是真正的像素图
  - **原因**：AI 生成 + 自动去背景的常见问题；AI 画的像素风没有统一网格
  - **解决**：新增 `tools/pixelize.py`：透明度低于一半的变全透明、去掉灰色污渍 → 自动寻找最合适的网格起点 → 每 12.5px 合成一个像素（取格子中间出现最多的颜色）→ 合并成 15 种颜色 → 裁掉空白。结果 124×55 像素、3.5 KB，每个像素要么全透明、要么完全不透明
- **欢迎页换用 wings.png**：一对像素翅膀作为背景（窄屏 2 倍 248×110、≥420px 3 倍 372×165，`image-rendering: pixelated` 保持像素清晰），白蛋居中叠在两翅之间的空隙（图片第 58–63 列，约 48.8%）；wings-raw.png 移到 design-refs/，不提交
- **问题**：用无头 Chrome 截图时，第一次页面空白，第二次缺了背景图，手机宽度的截图右侧被截断
  - **原因**：`--virtual-time-budget` 会"快进"时钟，导致页面等待的 IndexedDB 一直没返回；背景图还没加载完就截了图；无头 Chrome 的窗口最小宽度约 500px，设成 390 时页面其实按 ~500px 排版再被裁掉
  - **解决**：改用真实等待（`--timeout=8000`）；手机截图改为在临时页面里放一个 390px 宽的 iframe 加载网页，再裁出 iframe 区域（临时页面截完即删）
- **问题**：欢迎页的翅膀太大，和蛋的比例不协调
  - **原因**：翅膀按整数倍放大，屏幕 ≥420px 时从 2 倍跳到 3 倍（372px 宽）；蛋的大小又按翅膀宽度的 32% 计算，两者都没有以蛋为基准；翅膀图两端还有闪光，显得更宽
  - **解决**：以蛋为基准：蛋固定 124px 宽，翅膀固定 248px（= 蛋宽 2 倍，也正好是 wings.png 的 2 倍整数缩放，像素清晰），手机和电脑尺寸一致、不随屏幕变化；不需要重新生成 wings.png
- **问题**：命令行 `chrome --screenshot` 截图仍然时好时坏（空白、缺图）
  - **原因**：它在 load 事件时就截图，本网页之后才读 IndexedDB、插入图片；没有"等所有图片加载完"的选项
  - **解决**：新增 `tools/screenshot.py`，通过 Chrome 调试协议控制浏览器：真实模拟 390px 手机屏幕，等"页面已渲染 + 字体加载完 + 1 秒内没有新网络请求"后再截图；只用 Python 自带模块
- **问题**：翅膀还是太大，而且根部贴着蛋（用户附草图：两只小翅膀分开、和蛋之间留空隙、位于蛋的中上部）
  - **原因**：一对翅膀是一张图，只能整体缩放，没法单独控制和蛋的间距
  - **解决**：用 `tools/split-wings.py` 把翅膀从中间空隙切成 wing-left.png / wing-right.png，分别定位；比例写成 CSS 变量（以蛋为基准）：每只翅膀最大宽 50% 蛋宽、最大高 33% 蛋高，和蛋之间空隙 8% 蛋宽，垂直中心在蛋高 45%（约 28%–61%），整体宽度 2.16 倍蛋宽
  - **取舍**：翅膀实际宽高比（约 1.05–1.1）比"50% 宽 × 33% 高"的框（1.26）更接近正方形，不变形的话两个比例不能同时满足；按"不超过"处理，以高度为准，实际宽度约为蛋宽的 42–43%。为保持像素清晰，曾试过把像素图重做得更粗（block 14）让翅膀正好 1 倍显示，但螺旋和闪光细节明显变差，所以保留原像素图，改为把蛋从 124px 调到 140px，这样 33% 蛋高 ≈ 55px ≈ 翅膀原始高度，接近 1 倍显示；320px 小屏上蛋缩回 124px
- **问题**：欢迎页的翅膀在上下浮动时线条抖动，电脑上很明显，手机上不太明显
  - **原因**：三个地方叠加：① 平滑动画让翅膀大部分时间停在小数像素位置（如 2.37px），像素图每一帧重新取样，有的像素忽宽忽窄；② 按比例算出的间距、位置是小数（如 11.2px、47.88px）；③ logo 按宽度缩放后高度是 88.56px，把下面所有元素推到半个像素上。电脑屏幕 1 个 CSS 像素 = 1 个物理像素，误差最明显；手机是 2–3 倍屏，误差被缩小
  - **解决**：所有算出来的尺寸、位置用 CSS `round(…, 1px)` 取整；logo 高度取整；浮动动画改用 `steps()`，每次移动整 1 像素（蛋和翅膀用同一个动画，保持同步）。用 Chrome 调试协议在电脑（1 倍屏）、手机（2 倍、3 倍屏）、320px 小屏上，在一个动画周期内各采样 312 个位置数值，全部落在整像素上
- **问题（未完全查明）**：用无头 Chrome 截图时偶尔整页空白，等 20 秒也不出现
  - **已知**：服务器日志显示那一次浏览器根本没有请求 schema.js、ui/modal.js、ui/form.js 三个文件；浏览器要等所有依赖的 JS 都加载完才运行页面代码，所以缺了它们页面就是空白。服务器端没有任何报错
  - **未知**：为什么这三个请求没发到服务器。之后连续 8 次都没能复现；推测和本地预览服务器默认只排队 5 个连接、浏览器同时请求 30 多个文件有关，但没有证实
  - **处理**：预览服务器连接队列改为 64；截图工具在页面 20 秒没加载完时自动重新加载一次。正式网站（GitHub Pages）和用户自己的浏览器都没出现过这个问题
- **问题**：改成 steps() 后线条不抖了，但浮动一顿一顿的，不顺滑
  - **原因**：6px 的浮动分 6 步，每次跳 1 像素，看起来就是卡顿
  - **解决**：恢复平滑的 ease-in-out 动画，但把蛋和翅膀放进同一个容器 `.welcome-float`，只对容器做动画并加 `will-change: transform`：浏览器在整像素位置把蛋和翅膀画好一次，再整体平移这张图，不会逐帧重新取样像素图，所以既顺滑又不抖。前提是里面元素的静止位置都是整像素（上一步已用 round 保证）
- **结果**：用户确认欢迎页翅膀浮动顺滑、线条不抖；三个按钮、载入示例、测试页 45 项全部通过

## 第 8 步：设置页（2026-10-11）
- **功能**：AI 设置（API 密钥、模型）；导出备份（全部数据 + 照片，一个 .json 文件，不含密钥）；导入备份（先检查、再确认、最后替换）；数据安全提示 + 持久存储状态 + 已用空间；一键清除示例数据
- **问题**：备份文件来自外部，内容不可信
  - **原因**：可能是别的文件、版本更新的备份、被改坏的文件，或混进了不是图片的"照片"
  - **解决**：导入前逐条检查：必须是 tamago 备份、版本能识别、每个人的编号 / 名字 / 分类 / 生日格式正确、每件礼物都能找到对应的人；任何一处不对就整份拒绝，现有数据不动。只保留已知字段；不是图片的照片去掉（礼物保留）；文件里的 API 密钥一律忽略，始终保留本机密钥；主数据和照片在同一个事务里写入，要么全部成功要么不变
- **问题**：截图工具对测试页一直等不到"页面就绪"；截设置页时总截到欢迎页；整页截图时底部导航盖住中间内容
  - **原因**：就绪检查只认网页主体的 #page；全新浏览器没有数据会跳到欢迎页，而"改地址 + 立即刷新"时刷新可能抢在跳转之前执行；整页截图时固定定位的导航画在第一屏底部
  - **解决**：没有 #page 时检查 body；新增 `--sample` 先载入示例数据，再经 about:blank 完整打开目标页；整页截图时把视口拉到页面高度再截
- **测试**：新增 8 项备份测试，共 53 项（无头 Chrome 中全部通过）
- **结果**：用户确认导出、导入往返、错误文件拒绝、清除示例、测试页 53 项全部通过
